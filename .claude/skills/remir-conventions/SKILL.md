# Remir conventions

## 1. Overview

The base package is `dev.luizhenriquevicari.remir`. Each module adds its own sub-package: `.core`, `.server` or `.app`.

**Everything in the repo is English**: identifiers, comments, table and column names, JSON fields, error codes and messages, UI strings (`strings.xml`) and docs.

| Module | Stack | Depends on |
|---|---|---|
| `core` | Plain Kotlin/JVM (not KMP): `@Serializable` DTOs, `@Resource`s, Konform validators | nothing in the project |
| `server` | Ktor 3, Exposed 1.x DSL, Postgres, Flyway (scripts generated by Exposed), Hikari, manual DI | `core` |
| `app` | Compose, Navigation (`@Serializable` routes), ViewModel + StateFlow, Koin, Ktor Client (OkHttp), Clerk | `core` |
| `build-logic` | convention plugins `remir.kotlin-jvm-library`, `remir.ktor-server`, `remir.android-app` | |

- Versions live only in `gradle/libs.versions.toml`.
- Shared build config lives in `build-logic/`; never copy it into modules.
- Local config lives in two git-ignored files:
  - `.env` holds the server and docker settings; `.env.example` is the committed template.
  - `local.properties` holds the **debug** app settings (`clerk.publishableKey`, `api.url`). Release builds never read it: they need the Gradle properties `remir.api.url` (https only) and `remir.clerk.publishableKey`, or the env vars `REMIR_API_URL` and `REMIR_CLERK_PUBLISHABLE_KEY`, and fail without them (see README). The release `BuildConfig` fields are set lazily in `androidComponents.onVariants`; keep script-member references out of those lambdas, or the configuration cache fails with "cannot serialize Gradle script object references".

## 2. Checklist: new feature `<feature>`

Use `profile` as the reference: every file below has a working counterpart there. Follow this order.

Path abbreviations:
- `C` = `core/src/main/kotlin/dev/luizhenriquevicari/remir/core`
- `S` = `server/src/main/kotlin/dev/luizhenriquevicari/remir/server`
- `A` = `app/src/main/kotlin/dev/luizhenriquevicari/remir/app`

1. **core**
   - `C/<feature>/<Feature>Dto.kt`: responses.
   - `C/<feature>/<Request>.kt`: request bodies. A file that holds a single class is named after it (`UpdateProfileRequest.kt`); several related requests may share `<Feature>Requests.kt`.
   - `C/<feature>/<Resource>.kt`: `@Resource` routes, same naming rule (`MeResource.kt`); several resources may share `<Feature>Resources.kt`.
   - `C/<feature>/<Feature>Validation.kt`: `object <Feature>Validation { val create = Validation<...> { } }`. Use the shared constraints in `C/validation/Constraints.kt`, and add new shared ones there.
2. **table**: `S/features/<feature>/XTable.kt` holds `object XTable : Table("snake_case_plural")` (the file is named after the table object). Every user-owned table has `val userId = varchar("user_id", 64).references(UsersTable.id).index()`.
3. **migration**: run `./gradlew :server:generateMigrations`, which writes `server/src/main/resources/db/migration/V<timestamp>__<description>.sql`. Review the generated SQL, then commit it. Never hand-write the DDL.
4. **server**
   - `S/features/<feature>/<Feature>Repository.kt`: Exposed DSL only; returns `core` DTOs.
   - `S/features/<feature>/<Feature>Service.kt`: business rules, opens `dbQuery { }`, throws domain exceptions.
   - `S/features/<feature>/<Feature>Routes.kt`: `fun Route.<feature>Routes(service)`.
   - Wiring: instantiate the Repository and Service in `S/Dependencies.kt`, and call the routes inside `authenticate(CLERK_AUTH) { }` in `S/plugins/Routing.kt`.
5. **app**
   - `A/features/<feature>/<Feature>Api.kt`: calls built on the `core` Resources.
   - `A/features/<feature>/<Screen>ViewModel.kt`: `data class <Screen>State` exposed as a `StateFlow`.
   - `A/features/<feature>/<Screen>Screen.kt`: `<Screen>Route` + stateless `<Screen>Screen` + `@PreviewLightDark` (inside `RemirPreview { }`).
   - UI text goes in `app/src/main/res/values/strings.xml`. A ViewModel never holds a `Context`: it exposes messages as `UiText` (`A/common/UiText.kt`: a server string or a `strings.xml` id) and the screen calls `asString()`.
   - Features are packaged by feature, not by layer. Keep a feature's files flat in `A/features/<feature>/` while it is small; once it passes about 6 to 8 files, split it into `data/` (Api) and `ui/` (Screens, ViewModels) sub-packages. A feature can hold several screens (list, detail, create).
   - Wiring: add a destination to `A/navigation/Routes.kt` (`Destination`), a `composable<>` in `A/App.kt`, and `singleOf(::XApi)` + `viewModelOf(::XViewModel)` in `A/di/AppModule.kt`.
6. **tests**: `server/src/test/kotlin/.../features/<feature>/<Feature>RoutesTest.kt`, using `remirTestApplication { }` and `TestJwt.token(...)`.
   - Cover at least: 401 without a token, the happy path, 400 with `fields`, and isolation between users (user A never sees user B's data).
   - `SchemaDriftTest` already guards the migration.
   - Add a `core` test when the validator has non-trivial rules.

Code examples for every layer: [examples.md](examples.md).

## 3. Inviolable rules

**core**
- No `java.*` in public types: use `kotlin.uuid.Uuid`, `kotlin.time.Instant`, and `kotlinx.datetime` for local dates.
- No dependency on Ktor server, Exposed, Android or Compose.
- No I/O and no business logic.

**Schema**
- Exposed `Table`s are the source of truth.
- Migrations come from `generateMigrations`. Never use `SchemaUtils.create` at runtime.
- Never edit a migration once it has been applied; generate a new one instead.

**Server layers**
- **Routes** do HTTP only: `receive`, `Validation.orThrow`, the service call, `respond`. No business `if`s, no DB access.
- **Service** is the only layer that opens a transaction (`dbQuery`). DB-dependent validation ("already exists") lives here and throws `Conflict`/`NotFound`.
- **Repository** maps `ResultRow` straight to `core` DTOs. No domain entities, no per-layer mappers.
- **Errors** are always domain exceptions (`NotFound`, `Conflict`, `Forbidden`, `ValidationFailed`). Only `StatusPages` turns them into `ApiError`; never `call.respond(HttpStatusCode.X, ...)` an error from a route.

**User data and auth**
- Every query filters by `call.userId()`. That is the Clerk `sub`, a `user_...` string, not a UUID. Never trust a user id that comes in a request body.
- Every API route sits inside `authenticate(CLERK_AUTH)`. The only exceptions are `GET /health` and the public legal pages `GET /legal/{type}` (they must open without an account for Google and store review).
- Admin routes call `call.requireAdmin()`: it reads the token's `metadata.role` claim (`admin`), which comes from the Clerk session token template (see README). Never trust an admin flag sent by the client.
- Legal documents (privacy policy, terms) live in the database as immutable Markdown versions (`legal_documents`); editing publishes a new version, never an update. User consent is recorded per version in `legal_acceptances`. HTML is produced by walking the Markdown tree into kotlinx.html (`features/legal/MarkdownHtml.kt`), never by concatenating HTML strings.
- The app fetches the Clerk token on every request through the `ClerkToken` plugin (`HttpClient.kt`). Never use `Auth { bearer { loadTokens } }`, and never store the token.

**App validation**: run the same `core` validator before calling the API. Local errors and `ApiError.fields` share the state's `fieldErrors: Map<String, String>`.

**Previews**: every design-system component and every screen has a `@PreviewLightDark` wrapped in `RemirPreview { }` (`designsystem/PreviewSupport.kt`), showing its meaningful states (default, loading, disabled, error). The only exception is what needs a real SDK, such as Clerk's `AuthView`. Render the preview in light and dark before calling a UI change done.

**Compose style**: prefer the idiomatic Compose form. An `if/else` that only chooses which UI to emit is fine; don't extract helpers just to dodge an `else`.

**Config and secrets**
- Server config comes only from env vars; for dev, `:server:run` loads `.env`.
- Docker values (ports, credentials) come from `.env`; nothing host-specific is hardcoded in `docker-compose.yml`.
- Production runs on Cloud Run (image from the `Dockerfile`) with Neon as the database; GitHub Actions (`.github/workflows/server.yml`) tests, builds, publishes and deploys on a push to `main`. Managed-Postgres settings are optional env vars: `DATABASE_SSLMODE` (`require` for Neon) and `DATABASE_POOL_SIZE`. The database password lives in Secret Manager, never in the repo or in a workflow. Setup is in the README ("Deploy").
- `.env`, `local.properties` and keystores are never committed.

**`applicationId = "dev.luizhenriquevicari.remir"`** never changes.

**No nested `if`s.** The only allowed exception is an error check. Flatten with early returns, `when`, or a helper.

**Lint is ktlint (formatting, `.editorconfig`, 120 columns) and detekt (`config/detekt/detekt.yml`).** Run `./gradlew ktlintFormat` to fix formatting and `./gradlew ktlintCheck detekt` to check; PRs run both. Fix the code instead of changing a rule or adding a baseline. The only agreed exceptions are `@Composable` function names in PascalCase and `ReturnCount` with guard clauses.

**No lint/type suppressions without asking Luiz first.** That covers `@Suppress`, `tools:ignore` and an `@OptIn` of an experimental API.

## 4. Anti-patterns

- Full Clean Architecture (domain/data/presentation layers, use cases).
- One-line use cases that only forward to a service or repository.
- Interfaces with a single implementation (`IProfileRepository`, `ProfileRepositoryImpl`): use the concrete class.
- Mappers between identical classes (Entity to Model to Dto).
- `sealed interface Action` / MVI by default: use public ViewModel functions instead.
- A client-side repository without cache/offline needs: the ViewModel calls the Api directly.
- Koin or any other DI framework on the server: DI is manual, in `Dependencies.kt`.
- `newSuspendedTransaction`, a blocking `transaction {}` in a route, `SchemaUtils.create`, or hand-written DDL.

## 5. Known pitfalls

| Symptom | Fix |
|---|---|
| `checkDebugAarMetadata`: "requires ... compile against version 37" | Navigation 2.10 and Compose BOM 2026.09 need `compileSdk 37` (`android-compileSdk` in the catalog). AGP 9.5 supports up to 37. |
| `Plugin [id: 'org.jetbrains.exposed.plugin'] was not found` | In a module's `plugins {}`, only plugins declared by `build-logic` resolve by id. That is why the `remir.ktor-server` convention applies the Exposed plugin through `pluginManager.apply`. |
| `org.jetbrains.kotlin.android` conflicts or duplicates | AGP 9 has built-in Kotlin: don't apply that plugin. The Kotlin version comes from KGP on the `build-logic` classpath; `kotlin { compilerOptions }` still works. |
| `Unresolved reference 'Table'` / `transaction` (Exposed) | Exposed 1.x moved its packages to `org.jetbrains.exposed.v1.core.*` and `...v1.jdbc.*`. `eq` also needs an import: `org.jetbrains.exposed.v1.core.eq`. |
| `newSuspendedTransaction` deprecated | Use `suspendTransaction` inside `withContext(Dispatchers.IO)`; `dbQuery` already does this. JDBC blocks, and without IO a row lock can deadlock. |
| `timestamp()` returns an unexpected type | `exposed-kotlin-datetime` uses `kotlin.time.Instant`. `kotlinx.datetime.Instant` was dropped in kotlinx-datetime 0.7+, and `Clock` is now `kotlin.time.Clock`. |
| Konform error key `.name`, or messages that read oddly | `dataPath` has a leading `.`: use `errors.byField()` (`Constraints.kt`). Prefer the shared constraints (`lengthBetween`, `notBlankTrimmed`...). |
| `generateMigrations` names files `V<timestamp>__...` | That is the plugin's default (`VersionFormat.TIMESTAMP_ONLY`), which avoids version clashes between branches. Flyway sorts them by version. |
| Testcontainers: `PostgreSQLContainer` deprecated or with an odd generic | Testcontainers 2.x uses the artifact `testcontainers-postgresql` and the non-generic class `org.testcontainers.postgresql.PostgreSQLContainer`. |
| `testApplication` tries to read the real env / DB | It loads `application.conf` and `module()` on its own. Use `remirTestApplication`, which sets `environment { config = MapApplicationConfig() }`. |
| Gradle 9: "Failed to load JUnit Platform" | `junit-platform-launcher` must be an explicit `testRuntimeOnly`; `configureJUnit()` in `build-logic` handles it. |
| Postgres 18 in Docker loses data or rejects the volume | From 18 on, the volume mounts at `/var/lib/postgresql`, not `/var/lib/postgresql/data`. |
| `docker compose up` fails with "missing in .env" | Run `cp .env.example .env`. If port 5432 is taken, change `DATABASE_PORT`. |
| Clerk: old `com.clerk:clerk-android` artifact | Use `clerk-android-api` + `clerk-android-ui` (1.x). |
| Clerk: screen flickers or skips post-sign-in steps | The gate uses `Clerk.isAuthFlowCompleteFlow`, not `userFlow`: AuthView still has steps after the user exists. |
| Clerk: `native_api_disabled` | Enable the Native API under Dashboard > Native applications. |
| Clerk: `getToken()`/`signOut()` never throw | They return `ClerkResult` (`Success`/`Failure`); handle it with `when`, as `ClerkSession` does. |
| Material3 `TopAppBar` asks for `@OptIn(ExperimentalMaterial3Api)` | Use `RemirTopBar` from the design system. The opt-in counts as a suppression and needs approval. |
| App on the emulator can't reach the server | Use `http://10.0.2.2:<PORT>/`, not `localhost`. Cleartext is only allowed in debug (`app/src/debug/res/xml/network_security_config.xml`). |
| App on a physical device can't reach the server | Run `adb reverse tcp:<PORT> tcp:<PORT>` and set `api.url=http://localhost:<PORT>/` in `local.properties` (`localhost` is already allowed in debug). It works on the emulator too, but the reverse is lost when adb restarts or the device reconnects. |
| Samsung (One UI): USB debugging blocked | Turn off Auto Blocker (Settings > Security and privacy > Auto Blocker), or its "Block commands by USB cable" option. |
| `Unresolved reference 'icons'` | `material3` does not bring the icons: add `compose-material-icons-core` (BOM-managed, no version) to the catalog and the module. |
| Build fails with `com/android/build/gradle/api/BaseVariant` right after "Configure Kotlin" | Studio injected `kotlin("jvm") version ...`, `jvmToolchain(8)` and `kotlin("test")` into the root and `app/build.gradle.kts`. Remove them: AGP 9 has built-in Kotlin and the toolchain comes from `build-logic`. |
| `URL(String)` deprecated on JDK 20+ | Use `URI(...).toURL()`. |
| `docker build` fails configuring `:app` (Android SDK not found) | The `Dockerfile` removes `:app` from `settings.gradle.kts` inside the build stage only. Don't try to install the SDK in the image. |
| Cloud Run domain mapping | It is **Preview**: Google does not recommend it for production (latency, no support). The next step is a global external Application Load Balancer; the code does not change. Keep the DNS record **DNS only** in Cloudflare. |

## 6. Commands

```bash
cp .env.example .env                   # once
docker compose up -d                   # local Postgres
./gradlew :server:run                  # API (loads .env)
curl localhost:8080/health             # ok
./gradlew :server:generateMigrations   # after changing a Table
./gradlew :core:test :server:test      # tests (Docker running)
./gradlew build                        # everything + lint
./gradlew :app:installDebug            # install on the emulator
```
